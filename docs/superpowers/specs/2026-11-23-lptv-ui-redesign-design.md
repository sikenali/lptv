# LPTV 播放器界面高保真重写（智慧屏 + CDE 通用）— 设计文档

日期：2026-11-23
状态：待审批（设计文档）

> 注：`frontend/` 已被 commit `7f68671` 删除；播放器**唯一源**为 `android/www/inject.js`。
> 智慧屏/CDE 实际运行 `lpk/content/web/web/inject.js`（由 `lpk/build.sh` 从 `android/www` 拷贝），
> Electron 打包产物 `electron/dist/linux-unpacked/resources/frontend/inject.js` 亦由 `android/www` 构建。

## 1. 意图与为什么

现有 LPTV 播放器（`android/www/inject.js`，3715 行，唯一源）是自绘的一套 DOM 风格，与产品最新设计稿不符。
用户要求：**直接改造**现有播放器界面，按 Calicat 设计稿 `2080555577832132608`（6 张界面图）
**高保真**还原，同时把已实现的功能**对接**起来；去掉录制、截图、悬浮窗、最大化；
播放/暂停逻辑不变；智慧屏与 CDE 桌面**通用**同一套界面。

目标产出：现有播放器在智慧屏(1280×720 全屏)与 CDE 桌面(窗口)上，界面与 6 张设计图一致，
功能（换台 / 频道面板 / 节目单 EPG / 播放暂停 / 切换台加载态）正常，且去掉 4 个功能。

## 2. 目标 / 非目标 / 反目标

### 目标
- 6 个设计状态全部高保真实现（见 §5 状态表）。
- 复用现有功能核心：频道数据/列表、EPG 数据获取、播放暂停、换台逻辑、切台加载态。
- 入口状态 = **频道首页**（用户拍板 A）。
- 智慧屏 + CDE 通用同一套 UI（共用 `frontend/inject.js`）。
- 去掉：录制(MediaRecorder)、截图、悬浮窗(小浮窗)、最大化按钮与相关逻辑。

### 非目标
- 不重写播放/暂停、换台、EPG 的**功能逻辑**（仅换界面）。
- 不新增录制/截图/浮窗/最大化（已删）。
- 不处理 CDE 容器 x264 软编 2s 顿挫（独立问题）。
- 不改变智慧屏/CDE **模式分离**（isTv/isSmartClient 判定与全屏/窗口逻辑保持）。

### 反目标（失败标准）
- 智慧屏被误判为桌面、或 CDE 桌面被误判为智慧屏（模式分离回归）。
- 换台卡死 / 位置错 / 黑边（智慧屏 3 问题回归）。
- 首开显示解码页（回归）。
- 功能（换台/EPG/暂停）因改界面而失效。

## 3. 约束

- **设计基准**：1920×1080。智慧屏实际画布 1280×720，CDE 窗口可变 → 必须以基准设计
  `transform: scale(viewportW/1920)` 整体缩放，且需与现有 `isFull` 钉位/全屏逻辑协调。
- **`android/www/inject.js` 为播放器唯一源**（`frontend/` 已删）。运行链：
  `android/www/inject.js` → `lpk/build.sh` → `lpk/content/web/web/inject.js`（智慧屏/CDE 运行），
  → `electron` 打包 `dist/.../resources/frontend/inject.js`。重写后需重生成这两处运行时副本。
  `android/android/app/src/main/assets/public/inject.js`（3587 行，APK 独立副本、与唯一源**不同**）——
  Android 原生 APK 用，若用户不要求可不动（见 §8）。
- **模式信号**：`isTv()`（渲染层）= `__lptvBridge===true || __LPTV_ENV.smart/isTv===true`；
  `switchChannel` 桥接分支回归 `__lptvBridge`（避免智慧屏 Electron 前端 IPC 递归死循环）。
  这些**不可破坏**。
- 字体：Inter + Noto Sans SC + remixicon（图标）。字号 8–62，字重 400–800。
- 数据来源：频道列表、EPG 从现有接口获取，不在前端硬编码。

## 4. 实现方案（唯一合理路径，用户已选「直接改造」）

在 `android/www/inject.js` 内**替换 UI 的 DOM/CSS 构造**为设计稿结构，保留功能函数（数据/换台/EPG/暂停），
新增 6 状态切换（见 §5），删除 4 功能。无独立 mockup、不重写逻辑 —— 故只有此一条路径。

### 权衡（被否决的替代）
- 先做独立高保真 HTML mockup 再接入：被否（用户要直接改造）。
- 重写逻辑层：被否（用户只要换界面，播放/暂停逻辑不变）。

### 我的技术决定（builder 可按此执行）
- **缩放**：以 1920×1080 为设计基准，`root` 用 `transform: scale()` 适配视口；监听
  `display-metrics-changed` / resize 重算，避免破坏现有 `isFull` 钉位。
- **入口**：启动进入「频道首页」；点卡片 → 「播放界面」。
- **全屏 vs 最大化**：保留全屏（智慧屏自动全屏 + `isFull` 钉位需要）；**删除最大化按钮+逻辑**
  （`lptv-tb-max`、`lptv-b-full` 的 maximize 部分）。悬浮窗(小浮窗)整个删除。
- **图标**：remixicon 类图标替换现有 inline SVG（设计稿用 remixicon）。
- **Android 镜像**：改完 `android/www/inject.js` 后由 `lpk/build.sh` 重生成 `lpk/content/web/web/`；
  重新打包 Electron dist；`android/android/app/src/main/assets/public/inject.js`（APK）默认不动。

### 状态机 / 导航
- 启动 → **状态1(频道首页)**（不自动播放，点卡片才播）。
- 状态1 点频道卡片 → **状态2(播放)**；换台中 → **状态6(加载)** → 状态2。
- 状态2 鼠标悬停（CDE）/遥控按键（智慧屏）→ **状态3(Hover 控制栏)**；离开/超时 → 状态2。
- 状态3 频道按钮 → **状态4(左侧频道面板)**；节目单按钮 → **状态5(右侧节目单面板)**；首页按钮 → 状态1。
- 状态4/5 关闭按钮 → 回到状态2/3；点频道/节目 → 相应动作 + 状态6。
- 智慧屏（无 hover）：OK/菜单/方向键呼出控制栏与面板，无操作定时自动隐藏。
